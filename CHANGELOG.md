# Changelog

All notable changes to mcc are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and mcc uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The same history is published at <https://luongnv89.github.io/mcc/changelog.html>.

## [Unreleased]

### Added

- `mcc config get|set|edit|path` reads and changes `~/.mcc/config.toml` without hand-editing TOML. `set KEY VALUE` accepts `sync.exclude`, `sync.extra` (comma-separated, `""` for none), `usage.show_email`, `usage.live` (`true`/`false`) and `profiles.ALIAS.label` (`""` removes it), checks the value as the command that uses it would, and saves through the comment-preserving, locked write; an invalid value is refused and the file is left unchanged. Keys other commands manage name that command instead. `get KEY` prints any key (dotted as in TOML; lists one item per line) and exits 1 when it isn't set. `edit` opens a copy in `$VISUAL`/`$EDITOR` and saves it only when it is valid mcc config (sync items, labels and `share_group` names included), offering to edit again otherwise. It holds no lock while the editor is open, and keeps your copy instead of saving when another command changed the file meanwhile. `path` prints the file's location. `get` and `path` never take the lock. ([#48](https://github.com/luongnv89/mcc/issues/48))
- `mcc env [PROFILE]` prints the shell line that points `CLAUDE_CONFIG_DIR` at the profile `mcc run` would start in the current directory (the project's default, else the default profile, which prints `unset CLAUDE_CONFIG_DIR`), or at PROFILE. It prints the fish form (`set -gx`) for fish, chosen with `--shell` or from `$SHELL`, and the bash form inside a direnv `.envrc`; paths are single-quoted, so spaces and quotes are safe. With `eval "$(mcc env)"` in a project's `.envrc`, plain `claude`, IDE extensions and scripts use the project's profile; the README documents the direnv setup. ([#42](https://github.com/luongnv89/mcc/issues/42))
- `mcc exec PROFILE -- CMD...` runs any command with a profile's `CLAUDE_CONFIG_DIR` and exits with its status, e.g. `mcc exec work -- claude mcp list`. `mcc exec --all -- CMD...` runs it once per profile, the default first, prints each profile's exit status, and exits 0 only when it succeeded everywhere (else with the first failing status). A command that can't be found counts as exit 127 (126 when it can't be run), and Ctrl+C stops at the current profile. Neither command takes mcc's config lock, so the command may run mcc itself. `env` and `exec` are reserved and can't be used as aliases. ([#43](https://github.com/luongnv89/mcc/issues/43))
- Versioned JSON output. `mcc list`, `mcc usage` and `mcc project list` take `--json-v2`, which prints `{"schema": 2, "profiles": [...]}` (`"projects"` for `mcc project list`) around the same objects as `--json`, so scripts can check the schema version before reading. `--json` is unchanged: still a bare array (schema 1, implicit), so `jq '.[]'` scripts keep working; within a schema, fields are only ever added. The README's *JSON output and its schema version* section documents both shapes and the deprecation path. ([#49](https://github.com/luongnv89/mcc/issues/49))
- Session-sharing groups and a cross-organization guard. `mcc share ALIAS --group NAME` shares only with the profiles of group NAME, through a store of its own (`~/.mcc/shared/groups/NAME/projects`), recorded as `share_group`; without `--group`, the profile's recorded group (else the `default` group, `~/.mcc/shared/projects`) is used, and moving to another group needs `--off` first. Joining a group whose profiles are in another organization, or whose account mcc can't identify, is refused unless `--allow-cross-org` is passed (recorded as `share_cross_org_allowed_at`, cleared by `--off`); organization ↔ personal is the strictest case and also needs a confirmation in a terminal. `mcc list` shows `(shared: NAME)` and `share_group` in `--json`. **Upgrade note:** profiles that already share keep `~/.mcc/shared/projects` as the `default` group's store, with nothing moved; a group that mixes organizations gets a warning, never a refusal. ([#40](https://github.com/luongnv89/mcc/issues/40))
- `mcc sync` is three-way. `add --clone` and `sync` record what they wrote in `<profile>/.mcc-sync.json` (a hash per path and MCP server), and the next sync compares the default, the profile and that record: a path changed only in the default is updated, one edited or deleted only in the profile is kept and reported as a local edit, and one changed in both (or added on both sides) is a conflict, kept unless `--force` (which backs it up to `.mcc-backup/` first, like every overwrite). `--dry-run` shows the classification and writes nothing, the record included. A profile without a record is compared two-way once. `mcc diff ALIAS [--only ITEMS]` lists each differing path with its class and a line diff, and `mcc list` has a `SYNC` column (`✓`, `3 behind`, `2 local edits`, `1 conflict`; `sync` in `--json`, a `Sync` row in `--long`). `sync.extra` entries naming `.mcc-sync.json` are rejected. ([#41](https://github.com/luongnv89/mcc/issues/41))
- `mcc add` records the account a profile logs in to under `[profiles.<alias>.account]` in `~/.mcc/config.toml` (email, account UUID, organization name and UUID, as Claude Code reports them), warns when another profile, the default included, is already logged in to the same account, and asks for an optional label (`personal`, the account's organization, or any text), kept as `label`. `--label LABEL` sets it without asking. `mcc list` has an `ORG` column, `--long` cards add `Organization ID` and `Label` rows, and `--json` adds `organization_uuid` and `label` per profile; `organization` (and `account`) fall back to the recorded account when the profile's `.claude.json` has none. ([#39](https://github.com/luongnv89/mcc/issues/39))
- Per-project profiles. `mcc project set PROFILE` makes PROFILE the one `mcc run` starts in the current git repository (or directory, or `--path DIR`). `--allow NAME` (repeatable or comma-separated) names the other profiles `mcc run` may offer when PROFILE is at its limit; setting the project again without it clears the list. `mcc project unset` and `mcc project list [--json]` manage them. They are kept as `[projects."<dir>"]` tables in `~/.mcc/config.toml`. `mcc rename` updates them, and `mcc delete` removes the ones naming the deleted profile and takes it off the allow lists.
- `mcc run [-- CLAUDE_ARGS]` starts Claude Code with the current project's default profile, or the default profile outside every project. mcc never switches accounts on its own. When that profile is at its 5-hour or weekly limit, `mcc run` asks what to do: waiting (starting nothing) is the default, starting it anyway comes next, and other profiles are offered only when the project allows them, by name and without their usage. Only that profile's usage is fetched. Without a terminal it stops (exit 2). `--profile NAME` starts NAME without checking usage. Starting a profile other than the project's, from the prompt or with `--profile`, prints a terms-of-service note on stderr. `--dry-run` prints the profile it would start. If the profile's usage can't be read, it starts. ([#31](https://github.com/luongnv89/mcc/issues/31))
- `mcc list` shows the project defaults under the profile table (project, profile and account, with `← here` for the current directory). `--long` cards have a `Default for` row, and `--json` has a `project_defaults` array per profile.
- `project` and `run` are reserved and can't be used as aliases.
- Opt-in `mcc statusline`, a Claude Code status-line shim. `mcc statusline install` backs up `~/.claude/settings.json` to `~/.mcc/backups/`, records the current `statusLine` and sets `mcc statusline` in its place (never twice); `--prefix` starts the status line with the active profile's name, e.g. `[work]`. On every refresh the shim works out the profile from `CLAUDE_CONFIG_DIR`, saves the session's `rate_limits` (5-hour and weekly `used_percentage` and `resets_at`) to `~/.mcc/state/<profile>/usage.json`, runs the previous `statusLine` command with the same stdin and prints its output, without taking mcc's lock or writing `~/.mcc/config.toml`. Profiles get it with their next `mcc sync`; when `[sync] exclude` has `settings`, `install` offers to add it to each profile directly (`--yes` accepts). `mcc statusline uninstall` restores the previous `statusLine` everywhere. `mcc rename` and `mcc delete` move or remove the profile's state, and `statusline` is reserved as an alias. ([#33](https://github.com/luongnv89/mcc/issues/33))
- A GitHub Actions CI workflow runs `cargo test` on Linux and macOS, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `shellcheck install.sh` and `brew audit` on the Homebrew formula for every push and pull request. ([#32](https://github.com/luongnv89/mcc/issues/32))

### Changed

- Internal: `mcc add`, `mcc rename`, `mcc refresh-launchers` and `mcc share` undo a failed run through one shared rollback helper (`src/txn.rs`) instead of four copies. Rollback order, messages and what is undone are unchanged. ([#50](https://github.com/luongnv89/mcc/issues/50))
- `mcc list`, `mcc usage` and `mcc run` read usage from the rate limits `mcc statusline` caches in `~/.mcc/state/<profile>/usage.json`, and no longer read any login by default. They show how old the numbers are (an `UPDATED` column, `Usage updated` in `mcc list --long`, `· 12m ago` in `mcc run`), treat a cached window whose reset time has passed as obsolete, and show `—` with a hint to run `/usage` in Claude Code for a profile with nothing current cached (`reason: "no_data"` in `--json`). The `usage` JSON object gains `source` (`cache` or `live`) and `updated_at`. **Upgrade note:** the live lookup, which reads each profile's OAuth token (from `.credentials.json` or the macOS Keychain) and calls Anthropic's undocumented usage endpoint, is now opt-in with `live = true` under `[usage]` in `~/.mcc/config.toml`; the first command that uses it prints a one-time disclosure, recorded as `live_disclosed_at`. `docs/privacy.html` describes the change. ([#34](https://github.com/luongnv89/mcc/issues/34))
- The session-sharing and `mcc run` terms-of-service notes, the README and the docs site now mention the updated Anthropic Usage Policy that takes effect November 12, 2026. The README and docs site quote the Team and Enterprise seat rules separately, each in its own words, document `MCC_NON_INTERACTIVE`, and `docs/PLAN.md` is marked as a historical plan. ([#38](https://github.com/luongnv89/mcc/issues/38))
- The full session-sharing note is printed only the first time sharing is turned on for a profile, and when is recorded as `share_note_acknowledged_at` under `[profiles.ALIAS]` in `~/.mcc/config.toml`. Later `mcc share` and `ALIAS --mcc-share` runs print a one-line reminder instead. ([#36](https://github.com/luongnv89/mcc/issues/36))

### Fixed

- `~/.mcc/logs/mcc.log` no longer grows without bound: once it reaches about 1 MB it is moved to `mcc.log.1` (replacing the previous one) before the next line is written, so at most about 2 MB of log, which can include account emails, is kept. A failed rotation never breaks a command. ([#51](https://github.com/luongnv89/mcc/issues/51))
- `mcc add` no longer warns about a duplicate account (and suggests `mcc delete`) when the same login is used in another organization, such as a personal plan and a work seat: those have usage limits of their own, so it prints a note instead. The warning stays for the same login in the same organization. ([#40](https://github.com/luongnv89/mcc/issues/40))
- The Keychain login lookup (live usage) no longer needs `USER`: when it is unset, as under launchd, cron or some IDE tasks, the account name comes from the password database (`getpwuid_r`) or `id -un`, so a logged-in profile is no longer reported as `not_logged_in`. ([#37](https://github.com/luongnv89/mcc/issues/37))
- Saving `~/.mcc/config.toml` keeps hand-written comments and formatting, and a command that changes nothing (such as `ALIAS --mcc-share` on a profile that already shares) no longer rewrites it. Every command that writes the config holds an advisory lock on `~/.mcc/.lock` from loading it to saving it, so concurrent runs no longer lose each other's changes; a command that has to wait says so. ([#35](https://github.com/luongnv89/mcc/issues/35))
- The `mcc project` and `mcc list` tests expected absolute project paths, but mcc shows a project under `$HOME` as `~/…`; they now expect what mcc prints, so they pass on Linux as well as macOS. ([#32](https://github.com/luongnv89/mcc/issues/32))
- `mcc sync` backs up every file or folder it overwrites or removes (such as `CLAUDE.md`, skills and agents) to `<profile>/.mcc-backup/<timestamp>/`, not only `settings.json`, `settings.local.json` and `.claude.json`, so edits made in a profile can be restored. A symlink is backed up as the link itself. `sync.extra` entries that are empty, `.` or inside `.mcc-backup` are rejected. ([#30](https://github.com/luongnv89/mcc/issues/30))

## [0.3.0] - 2026-10-13

Profiles can now opt in to session sharing with `mcc share ALIAS` or `ALIAS --mcc-share`, so `--resume` lists the sessions of every sharing profile, and `mcc refresh-launchers` updates launchers and shell aliases made by an older mcc.

### Added

- Opt-in session sharing between profiles, off by default. `mcc share ALIAS` (or starting a profile with `ALIAS --mcc-share`) links the profile's `projects/` to `~/.mcc/shared/projects`, so `--resume` lists the sessions of every sharing profile. `mcc share ALIAS --off` gives the profile its own copy again. The setting is `share_sessions` under `[profiles.ALIAS]` in `~/.mcc/config.toml`. Only sessions are shared: never credentials, the account, history or live session state. Every time sharing is turned on, mcc prints a note about Anthropic's Consumer Terms and Usage Policy. `mcc list` marks sharing profiles, and `--json` has `share_sessions` and `launcher_current`. ([#25](https://github.com/luongnv89/mcc/issues/25), [#26](https://github.com/luongnv89/mcc/pull/26))
- `mcc refresh-launchers [ALIAS...]` rewrites launchers and shell aliases from the current templates. ([#25](https://github.com/luongnv89/mcc/issues/25), [#26](https://github.com/luongnv89/mcc/pull/26))

### Changed

- New launchers handle `--mcc-share`, and new shell aliases run the launcher instead of calling `claude` directly. `CLAUDE_CONFIG_DIR` is unchanged, so logins are kept. **Upgrade note:** existing launchers and aliases are not modified; run `mcc refresh-launchers` once to use `ALIAS --mcc-share` with profiles created before this release. ([#25](https://github.com/luongnv89/mcc/issues/25), [#26](https://github.com/luongnv89/mcc/pull/26))
- `mcc list` prints a hint to run `mcc refresh-launchers` while a launcher predates session sharing. ([#25](https://github.com/luongnv89/mcc/issues/25), [#26](https://github.com/luongnv89/mcc/pull/26))
- `share` and `refresh-launchers` are reserved and can't be used as aliases. ([#25](https://github.com/luongnv89/mcc/issues/25), [#26](https://github.com/luongnv89/mcc/pull/26))

## [0.2.0] - 2026-10-13

`mcc usage` is now a compact table that hides account emails by default, and `mcc rename` renames a profile and its command while keeping its login.

### Added

- `mcc rename ALIAS NEW` (alias `mv`): renames a profile and its command. It installs the new launcher and alias block, renames the registry entry, then removes the old launcher and alias. The new name is checked like an alias in `mcc add`, and a failure rolls the changes back. The profile directory, and so its login, is kept. ([#24](https://github.com/luongnv89/mcc/issues/24), [#23](https://github.com/luongnv89/mcc/pull/23))
- `[usage] show_email` in `~/.mcc/config.toml`, plus `--show-email` / `--hide-email` on `mcc usage`, to choose whether account emails are shown. ([#24](https://github.com/luongnv89/mcc/issues/24), [#23](https://github.com/luongnv89/mcc/pull/23))

### Changed

- `mcc usage` shows a compact table, one row per profile, instead of a block per profile: `PROFILE`, then the bar and percent used, time until reset and reset time for the 5-hour and weekly windows. On narrow terminals the reset time goes first, then bars shrink 10 → 5 → 0. ([#24](https://github.com/luongnv89/mcc/issues/24), [#23](https://github.com/luongnv89/mcc/pull/23))
- `mcc usage` hides account emails by default, in the table and in `--json` (`account` is `null`). Use `--show-email` or `[usage] show_email = true` to show them. ([#24](https://github.com/luongnv89/mcc/issues/24), [#23](https://github.com/luongnv89/mcc/pull/23))
- `mcc add <old name>` names the renamed profile that still uses that name's directory, instead of only saying that the directory exists. ([#24](https://github.com/luongnv89/mcc/issues/24), [#23](https://github.com/luongnv89/mcc/pull/23))

### Fixed

- `mcc delete <old name>` refuses to delete a directory that a renamed profile still uses. ([#24](https://github.com/luongnv89/mcc/issues/24), [#23](https://github.com/luongnv89/mcc/pull/23))

## [0.1.0] - 2026-10-10

The first version of mcc.

### Added

- Homebrew formula for macOS and Linux: `brew install luongnv89/tap/mcc` builds mcc from source and installs bash, zsh and fish completions. `brew upgrade mcc` and `brew uninstall mcc` work as usual. The formula lives in `packaging/homebrew/mcc.rb`. ([#14](https://github.com/luongnv89/mcc/issues/14))
- `mcc usage [PROFILE] [--json]`: every profile's 5-hour and weekly usage in detail, with a bar, percent used and left, time until reset, and the reset time in local time. `default` or `claude` selects `~/.claude`; an unknown name exits 2. ([#16](https://github.com/luongnv89/mcc/issues/16), [#20](https://github.com/luongnv89/mcc/pull/20))
- Usage meters in `mcc list`: a coloured bar (green, yellow at 80%+, red at 95%+) and colour-independent `!` / `!!` markers, sized to the terminal width. ([#17](https://github.com/luongnv89/mcc/issues/17), [#20](https://github.com/luongnv89/mcc/pull/20))
- 5-hour and weekly usage in `mcc list`: new `5H` and `WEEK` columns, lines in `--long` cards, and a `usage` object in `--json`, for every profile including the default. Each profile's own login is used; failures show `unavailable` with a reason and never change the exit status. ([#13](https://github.com/luongnv89/mcc/issues/13), [#15](https://github.com/luongnv89/mcc/pull/15))
- `--no-usage` and `MCC_NO_USAGE` to skip the usage fetch, and the `MCC_USAGE_URL` / `MCC_SECURITY_BIN` test overrides. ([#15](https://github.com/luongnv89/mcc/pull/15))
- `mcc completions` for bash, zsh, fish, elvish and PowerShell, plus `install.sh`. ([#12](https://github.com/luongnv89/mcc/pull/12))
- `mcc list` (table, `--long` cards, `--json`), `mcc sync` (plan, backup, apply; `--dry-run`, `--prune`, `--only`, `--all`) and `mcc delete` (type-to-confirm or `--yes`, logout, removes only what mcc created). ([#12](https://github.com/luongnv89/mcc/pull/12))
- `mcc init` (OS, terminal, shell, rc file and `claude` detection, run automatically on first use) and `mcc add` (alias validation, clone with path rewriting, launcher, managed rc block, login, rollback on failure). ([#12](https://github.com/luongnv89/mcc/pull/12))
- Apache-2.0 license, contributing guide, code of conduct, security policy, and issue and pull request templates. ([#18](https://github.com/luongnv89/mcc/issues/18), [#19](https://github.com/luongnv89/mcc/pull/19))

### Fixed

- `mcc usage` keeps the full 20-cell bar at 80 columns: it drops the absolute reset time before shrinking the bar, and shrinks in the same 20/10/0 steps as `mcc list --long`. ([#21](https://github.com/luongnv89/mcc/pull/21))
- Relative symlinks (such as `skills/x -> ../../.agents/skills/x`) are re-resolved from their source location, so cloned profiles don't get broken links. ([#12](https://github.com/luongnv89/mcc/pull/12))

### Security

- Access tokens are kept in memory only, sent only to the usage endpoint for their own profile, and never printed, logged or written to disk. Expired tokens are never sent. ([#15](https://github.com/luongnv89/mcc/pull/15))
- GitHub private vulnerability reporting is enabled, and `contact@luongnv.com` is listed as the security contact. ([#21](https://github.com/luongnv89/mcc/pull/21))
