Privacy policy

mcc runs on your computer. It has no accounts, no telemetry and no analytics, and the project receives no data from you.

Summary #

No telemetry

mcc does not report usage, crashes or any other data to the project or anyone else.

Local files only

Everything mcc stores stays in your home directory, mostly under ~/.mcc.

No tokens read by default

Usage comes from what mcc statusline cached on your machine, and login expiry from the date stored next to each login, not the login itself. Asking Anthropic with each account's login, or Devin with the Devin CLI's, is an opt-in.

No cookies on this site

This website sets no cookies and loads no analytics, fonts or scripts from other hosts.

What mcc reads #

To do its job, mcc reads these files and settings on your computer. None of it leaves your machine except as described under Network requests.

  • Your Claude Code setup: ~/.claude, ~/.claude.json and each profile directory, to copy, sync and count settings, skills, agents, plugins, MCP servers and hooks, and to show when each profile was last active (from the modification times of its prompt history and transcripts, never their contents).
  • Your shell environment: your OS, terminal, shell, $PATH, and your shell rc files (.zshrc, .bashrc, fish config and similar), to check that a new alias doesn't clash with an existing command and to manage its own alias block.
  • Cached usage: the rate limits mcc statusline, or the last mcc usage --all, saved in ~/.mcc/state/<profile>/usage.json (percent used and reset times only), which mcc list, mcc usage and mcc run show by default.
  • Login expiry dates: mcc usage reads one date from each profile's .credentials.json, when its login needs a new sign-in (refreshTokenExpiresAt), and sends nothing. It reads that date from the profile's macOS Keychain item too only with the live usage lookup or mcc usage --all, and with MCC_NO_USAGE=1 it reads nothing. mcc login reads the same date from the file and, on macOS, the Keychain item before and after it renews a profile's sign-in, and mcc login --refresh-only also reads when the access token expires (expiresAt), as does mcc usage --all for an account whose token it finds expired, before and after it has Claude Code refresh it. Only these dates are taken: the tokens stored with them are skipped, never kept or sent.
  • Claude Code access tokens, only if you turn on the live usage lookup (live = true under [usage] in ~/.mcc/config.toml; off by default) or run mcc usage --all (that one run only, with a risk notice each time): the access token in each profile's .credentials.json, or on macOS in the Keychain item Claude Code created for that profile, under your login name ($USER, or the system's name for your user when USER is unset). The access token is held in memory for the request and then discarded.
  • The Devin CLI's login: mcc checks whether Devin's credentials.toml exists ($XDG_DATA_HOME/devin/credentials.toml, else ~/.local/share/devin/credentials.toml) to show a devin row, and reads the session token in it only for the live usage lookup (live = true), mcc usage --all, or, with live = true, mcc doctor's check that the file holds a token (never sent or shown). The token is held in memory only while mcc uses it, then discarded. mcc never changes that file.
  • An API key you give mcc add: with --api-key-stdin or --api-key-prompt, mcc reads an Anthropic API key from a pipe or a hidden prompt and writes it once to a file (see What mcc stores). It never reads that file again and never sends the key anywhere; Claude Code reads it when it needs the key. With --api-key-helper, mcc stores no key and never runs your command. A key is never taken as a command-line argument, and a value that looks like one is redacted from mcc's log.
  • Session cost, for an API-key profile only: the status line receives each session's ID and running cost from Claude Code, which mcc adds up into this month's estimated spend.
  • Account status: mcc runs claude auth status to show which account each profile is signed in to.

What mcc stores #

mcc writes only to your home directory (or to MCC_HOME if you set it), except that mcc login --refresh-only, and mcc usage --all when it refreshes the token of a profile no project maps to, create an empty, private folder in the system's temporary directory for that one request and remove it when the request ends:

LocationContents
~/.mcc/config.tomlDetected environment (OS, shell, rc file, claude path), the list of profiles, the account each mcc profile signed in to as Claude Code reports it (email, account ID, and organization name, ID and type), each profile's label and color, project defaults, the other machines you list for mcc usage (their names, SSH hosts and mcc paths), each API-key profile's monthly budget, your settings, and when one-time notes (such as the live usage lookup disclosure) were shown
~/.mcc/.lockAn empty file that mcc commands lock while they change config.toml, so two runs don't lose each other's changes
~/.mcc/state/<profile>/After mcc statusline install or mcc usage --all: the 5-hour and weekly rate limits (percent used and reset time), cached by the status line or saved by the last mcc usage --all, and the statusLine setting the shim replaced (only after mcc statusline install). With auto sync, on by default: auto-sync.json, when it last checked the profile, when it last copied something and which paths, what it held back, and a hash of what it compared. refresh.lock, an empty file locked while mcc usage --all or mcc login --refresh-only has Claude Code refresh the profile's token, and refresh-failed-at, the time mcc usage --all last failed to, so it waits 30 minutes before trying again. No login, token or file contents
~/.mcc/providers/devin/quota.jsonAfter a successful live lookup of Devin's usage: Devin's daily and weekly percent used and reset times, its overage balance, and the organization (ID and name) the quota is for. No token
~/.mcc/keys/Only for an API-key profile added with --api-key-stdin or --api-key-prompt: its Anthropic API key, the one credential mcc stores, in a file only you can read (0600, in a 0700 folder). Claude Code reads it through the profile's apiKeyHelper; mcc never reads it again. mcc delete removes it unless you pass --keep-auth
~/.mcc/state/<profile>/cost/Only for an API-key profile: one small file per Claude Code session with the last cost the status line saw and what the session added in each month, for the estimated spend. Files left alone for 62 days are removed. No key, prompt or conversation
~/.mcc/profiles/<alias>/Each profile's Claude Code configuration. Claude Code itself stores that profile's login and history here
<profile>/.mcc-sync.jsonThe paths, MCP server names and settings.json keys mcc last copied into the profile, each with a hash of what it wrote, so mcc sync can tell your edits from the default's changes, and a hash of each secret setting, or setting only that profile had, you declined to sync. No file contents or setting values
~/.mcc/shared/projects/, ~/.mcc/shared/groups/<name>/projects/Session transcripts of the profiles you opted in with mcc share, one store per group. They exist only once sharing is turned on
~/.mcc/logs/mcc.logA log of each command's steps and results, which can include file paths and a profile's account email. It never contains access tokens. At about 1 MB it is moved to mcc.log.1, replacing the previous one, so at most about 2 MB of log is kept

~/.local/bin/<alias> and your rc fileThe launcher for each profile and a marked alias block

Results of the live lookup turned on with live = true are shown and discarded; mcc does not save them. mcc usage --all saves only the percentages and reset times it finds, in ~/.mcc/state/<profile>/ as above, never the token. Devin's usage is the exception to the first rule: each successful live lookup of it, with live = true or --all, is saved to ~/.mcc/providers/devin/quota.json as above, never the token.

Network requests #

Usage lookups (opt-in)

By default mcc list, mcc usage and mcc run make no network request for usage: they read the statusline cache. Only with live = true under [usage] in ~/.mcc/config.toml, or for one run of mcc usage --all, does mcc send one HTTPS request per signed-in profile, the default included, to Anthropic's undocumented usage endpoint, https://api.anthropic.com/api/oauth/usage. With live = true the first such command prints a one-time disclosure; mcc usage --all prints a risk notice every time it runs. Each request carries:

  • that profile's own access token, in the Authorization header
  • a User-Agent of mcc/<version>

Anthropic returns the percent of the 5-hour and weekly limits used and when they reset. A token is never sent to any other host, never sent for another profile, and never sent once it has expired. mcc itself never refreshes a token: it never sends a refresh token or calls the OAuth token endpoint. When mcc usage --all finds a token expired, it has Claude Code refresh it (see below), then sends the refreshed token once more, for that profile alone.

The only exception is the MCC_USAGE_URL override, intended for testing. It accepts only https:// URLs or http:// on your own machine (loopback); any other value is refused and nothing is sent.

When the Devin CLI is signed in, the same two switches also look up Devin's usage. mcc sends the Devin CLI's session token, in the Authorization header with the same User-Agent, to Devin's API at https://app.devin.ai/api: to /organizations when it doesn't know your organization yet, or once more when Devin refuses the one it saved, then to /<organization>/billing/quota/usage with the organization ID. With live = true the first such command prints a one-time note; mcc usage --all adds a line about Devin to its risk notice. Devin returns its daily and weekly quota and overage balance. The token is never sent to any other host, and the MCC_DEVIN_API_URL test override accepts only https:// URLs or loopback http://.

Your other machines (opt-in)

Only when you list other machines under [machines.NAME] in ~/.mcc/config.toml does mcc usage connect anywhere over SSH, and only to those hosts: it runs ssh -o BatchMode=yes with your own SSH keys and configuration (mcc never reads ~/.ssh/config itself) to run mcc usage on each of them. No login or token is sent between machines: each machine looks up its own accounts with its own login. What comes back is that machine's usage table: profile names, percentages, reset times, when each profile was last active, login expiry dates, when each profile's numbers were last updated and, for each account, a SHA-256 hash of its email and its organization's ID (to match the same account across machines). Emails are never sent, whatever show_email says on either machine. That hash is a pseudonym, not a secret: someone who already knows an email and its organization's ID can check whether it matches. mcc usage --json-v2 prints it as account_id. When another machine has newer numbers for an account this machine has too, mcc saves those percentages and reset times, with when they and this machine's own numbers were last updated, to ~/.mcc/state/<profile>/usage.json, as mcc usage --all does. The first time, mcc usage explains this on stderr, and records when in ~/.mcc/config.toml. mcc usage PROFILE, --json and MCC_NO_USAGE=1 never connect.

mcc remote PROFILE MACHINE TASK also uses those hosts, only when you run it. Claude Code runs on this machine as the profile, and the task you give it and the commands Claude writes are normal Claude Code usage: they go to Anthropic with that profile's login, as any Claude Code prompt does. The commands go to the machine over SSH, with your own key and configuration, and their output comes back to Claude Code. mcc sends no login or token to the machine. The task goes to Claude Code on its input, not on a command line, and is never written to mcc's log, which records only the profile, the machine and how the run ended; a record of each command's exit status (never the command) is kept in a private folder under ~/.mcc/state/remote/ for the run and removed with it.

Claude Code sign-in and sign-out

mcc add and mcc login run claude auth login, and mcc delete runs claude auth logout. mcc login --refresh-only instead runs one small claude -p request on the haiku model, in an empty folder and without your tools, MCP servers or hooks, so that Claude Code refreshes the profile's access token itself; it spends a little of that account's usage, and runs nothing while the access token is still valid. mcc usage --all runs the same request for each account whose token it finds expired, announced on stderr first, in a project you mapped to that profile with mcc project set, where Claude Code reads the project as in any session there (its git status and CLAUDE.md), or, for a profile no project maps to, in an empty temporary folder. Those are Claude Code's own commands. They talk to Anthropic under Anthropic's terms, and mcc does not see your password or the sign-in exchange.

Installing mcc

The install script downloads a prebuilt mcc binary and its SHA-256 checksum from mcc's GitHub releases, over HTTPS only. It builds from source instead, as cargo install and brew install do, when a release has no binary for your platform, with MCC_FROM_SOURCE=1, or when run from a clone. Building downloads mcc's source from GitHub and its dependencies from crates.io, and Homebrew also downloads its own Rust to build mcc. Those services see the request like any other download.

mcc makes no other network requests.

Third parties #

  • Anthropic receives the usage requests described above, if you turn them on, and handles Claude Code sign-in, including the request mcc login --refresh-only and mcc usage --all have Claude Code make. See Anthropic's privacy policy.
  • Devin receives the Devin usage requests described above, if the Devin CLI is signed in and you turn them on. mcc devin only starts the Devin CLI, which talks to Devin under Devin's own terms; mcc does not see that exchange.
  • GitHub hosts the source code, the install script, the release binaries and this website. See the GitHub General Privacy Statement.
  • crates.io serves Rust dependencies when you build mcc. See the Rust Foundation privacy policy.
  • Homebrew, if you install mcc with it, serves the Rust used to build mcc and has its own analytics. See Homebrew's analytics page.

mcc is an independent project and is not affiliated with Anthropic.

This website #

This site is a set of static pages served by GitHub Pages. It sets no cookies, runs no analytics or tracking, and loads no fonts, scripts or images from other hosts. The only script is a small local file that adds copy buttons, highlights the table of contents and plays the terminal demo on the home page.

GitHub, as the host, may log technical information about visits, such as IP addresses, for security and operation. That is covered by GitHub's privacy statement, linked above. The project has no access to those logs.

Your control #

  • Live usage lookups are off unless you set live = true under [usage], or run mcc usage --all for a single lookup; set live back to false (or remove it) to stop them. mcc list --no-usage or MCC_NO_USAGE=1 skip usage entirely, cache included; MCC_NO_USAGE=1 also stops mcc usage reading login expiry dates.
  • Remove a profile with mcc delete <alias>. It signs the profile out and deletes its directory, launcher and alias block, and the API key file mcc wrote for it.
  • Reading other machines is off unless you list them under [machines] in ~/.mcc/config.toml; remove them with mcc config edit to stop.
  • Remove everything by following Uninstall, which ends with rm -rf ~/.mcc.

Because the project never receives your data, there is nothing for it to export or delete on your behalf.

Changes #

If mcc's data handling changes, this page and the changelog will say so, and the effective date above will change. The full history of this page is in the repository.
