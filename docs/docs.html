Overview #

mcc runs several Claude Code accounts side by side. Each account gets its own login, its own command, and the same setup as your main one.

Claude Code reads its configuration from the directory in CLAUDE_CONFIG_DIR, which defaults to ~/.claude. mcc gives each extra account its own directory under ~/.mcc/profiles/ and a command that sets the variable before starting claude. It then keeps those profiles in sync with your default setup.

mcc supports macOS and Linux with zsh, bash or fish.

Install #

You need Rust (cargo, Rust 1.88 or newer) and Claude Code. If you don't have Rust, install it from rustup.rs.

One-liner

$ curl -fsSL https://raw.githubusercontent.com/luongnv89/mcc/main/install.sh | sh

From a clone

$ git clone https://github.com/luongnv89/mcc && cd mcc && ./install.sh

Directly with Cargo

$ cargo install --git https://github.com/luongnv89/mcc --locked

The install script checks your platform and cargo, builds mcc, and installs the binary into ~/.cargo/bin (override with CARGO_INSTALL_ROOT). Check it worked:

$ mcc --version

Quick start #

$ mcc init                    # detect your environment (also runs automatically the first time)
$ mcc add work --clone        # new profile with your default setup, then log in
$ work                        # start Claude Code as the "work" account
$ mcc list                    # see all profiles
$ mcc usage                   # how much of each account's limits is used
$ mcc sync work               # later: pull new skills/plugins/settings from the default
$ mcc delete work             # remove it completely

After mcc add finishes, the new command works in any shell straight away, because the launcher is written to ~/.local/bin. The shell alias takes effect in new terminals.

Concepts #

Default profile

Your existing Claude Code setup: ~/.claude plus ~/.claude.json, started with claude. mcc never writes into it during sync. If ~/.claude doesn't exist yet, mcc add creates it as the default profile first.

mcc profiles

Each additional account. A profile is a directory at ~/.mcc/profiles/<alias>/ used as CLAUDE_CONFIG_DIR, a launcher at ~/.local/bin/<alias>, a managed alias block in your shell rc file, and an entry in ~/.mcc/config.toml.

Clone or fresh

When you add a profile you choose how it starts:

  • Clone (--clone) copies the default profile's setup: settings, CLAUDE.md, skills, agents, commands, hooks, plugins and MCP servers. It never copies credentials. See Clone & sync rules.
  • Fresh (--fresh) starts with an empty profile.

Sync

A one-way copy from the default profile into a profile. Most tools assume the default config path, so the default stays the source of truth and profiles follow it.

mcc init #

mcc init [--force] [--shell zsh|bash|fish]

Detects your OS, architecture, terminal, shell, rc file, the claude binary, and whether ~/.local/bin is on your PATH (and offers to add it). The result is saved in ~/.mcc/config.toml. It runs automatically the first time you use mcc.

OptionEffect
--forceRe-run detection even if mcc is already initialized
--shell <SHELL>Shell whose rc file mcc manages: zsh, bash or fish (default: detected from $SHELL)
 
$ mcc init
$ mcc init --force --shell bash

mcc add #

mcc add [ALIAS] [--clone | --fresh] [--no-login] [-y]

If ~/.claude doesn't exist, add creates your default profile. Otherwise it creates a new profile in eight numbered steps:

  1. Validate the alias (see Alias rules)
  2. Create ~/.mcc/profiles/<alias>
  3. Copy the setup from the default profile (clone only)
  4. Install the launcher ~/.local/bin/<alias>
  5. Add the shell alias to your rc file (backed up first)
  6. Register the profile in ~/.mcc/config.toml
  7. Log in with claude auth login; finish the sign-in in your browser
  8. Verify the login and show the account

If a step fails, the changes made so far are rolled back. Without an alias or a --clone/--fresh flag, add asks interactively.

OptionEffect
ALIASCommand name for the new profile (prompted if omitted)
--cloneCopy the default profile's setup (never credentials)
--freshStart with an empty profile
--no-loginSkip claude auth login; log in later by running the alias
-y, --yesAccept defaults without prompting
 
$ mcc add                         # interactive: asks for the alias and clone/fresh
$ mcc add work --clone            # copy the default's setup, then log in
$ mcc add lab --fresh --no-login  # empty profile; log in later by running `lab`

mcc list #

mcc list [--json | -l/--long] [--no-usage] alias: mcc ls

One row per profile, the default included: command, account, 5-hour and weekly usage (with a bar), skills, agents, commands, plugins (enabled/installed), MCP servers, hooks, size, last used and last sync.

OptionEffect
--jsonPrint JSON to stdout instead of a table
-l, --longShow a detailed card per profile
--no-usageSkip fetching usage: no network, no keychain (same as MCC_NO_USAGE=1)
 
$ mcc list
NAME       COMMAND  ACCOUNT         5H                     WEEK                   SKILLS  …
default ★  claude   me@example.com  ████░░░░░░ 42% (2h)    ██░░░░░░░░ 18% (3d)         2  …
work       work     work@corp.com   █████████░ 85%! (35m)  ██████████ 96%!! (3d)       2  …
lab        lab      —               unavailable            unavailable                 0  …
$ mcc list --long
$ mcc list --no-usage            # offline: skip the usage lookup
$ mcc list --json | jq '.[] | {name, account, skills, plugins_installed}'
$ mcc list --json | jq '.[] | {name, five_hour: .usage.five_hour.percent, weekly: .usage.weekly.percent}'

mcc usage #

mcc usage [PROFILE] [--json]

Shows only usage, in more detail than list: a bar, percent used and left, time until reset, and the reset time in your local time zone. Pass a profile name to see just one; use default or claude for ~/.claude. An unknown name is a usage error (exit 2).

OptionEffect
PROFILEOnly this profile (default or claude for the default)
--jsonPrint one JSON object per profile with name, command, is_default, account and usage
 
$ mcc usage                       # every profile, the default included
$ mcc usage work                  # only the `work` profile
$ mcc usage --json | jq '.[] | {name, weekly: .usage.weekly.percent}'

See Usage limits for how to read the output and where the data comes from.

mcc sync #

mcc sync (ALIAS | --all) [--dry-run] [--prune] [--only ITEMS] [-y]

Copies the default profile's setup into a profile. It plans the changes, backs up the profile's settings.json, settings.local.json and .claude.json to <profile>/.mcc-backup/<timestamp>/, then applies them with progress.

OptionEffect
ALIASProfile to update (required unless --all)
--allSync every mcc profile
--dry-runShow what would change without writing anything
--pruneAlso remove items that exist in the profile but not in the default (asks for confirmation)
--only ITEMSComma-separated list of items to sync: settings, claude-md, keybindings, statusline, agents, skills, commands, hooks, output-styles, plugins, mcp
-y, --yesDo not ask for confirmation
 
$ mcc sync work --dry-run               # preview what would change
$ mcc sync work --only skills,agents    # only some items
$ mcc sync --all --prune --yes          # make every profile mirror the default exactly

mcc delete #

mcc delete ALIAS [-y] [--keep-auth] alias: mcc rm

Logs the profile out with claude auth logout (clearing its keychain entry), then removes its directory, launcher, shell alias block and registry entry. It asks you to type the name to confirm unless you pass --yes. It refuses to delete the default profile, and only removes launchers that mcc created.

OptionEffect
-y, --yesSkip the confirmation prompt
--keep-authDo not run claude auth logout before deleting
 
$ mcc delete lab
$ mcc delete lab --yes --keep-auth

mcc completions #

mcc completions bash|zsh|fish|elvish|powershell

Prints a completion script to stdout. It has no first-run side effects.

$ mcc completions zsh  > ~/.zfunc/_mcc        # with fpath+=~/.zfunc in ~/.zshrc
$ mcc completions bash > ~/.local/share/bash-completion/completions/mcc
$ mcc completions fish > ~/.config/fish/completions/mcc.fish

Clone & sync rules #

What is copied

Item (--only name)Paths
settingssettings.json, settings.local.json
claude-mdCLAUDE.md
keybindingskeybindings.json
statuslinestatusline.conf
agents, skills, commands, hooks, output-stylesthose directories
pluginsplugins/installed_plugins.json, plugins/known_marketplaces.json, plugins/marketplaces/, plugins/cache/
mcpthe mcpServers entry from ~/.claude.json, merged; the rest of the profile's state is kept

Never copied: credentials, account identity (oauthAccount, userID), history, projects and sessions, todos, telemetry, caches and file history.

Path rewriting

Each profile uses its own copies. In settings, plugin manifests and MCP server entries, any ~/.claude/…, $HOME/.claude/… or /Users/you/.claude/… path that points at a copied item (for example ~/.claude/hooks/notify.sh) is rewritten to the profile directory.

Paths to things that aren't copied, such as ~/.claude/statusline/run.sh, keep pointing at the default profile, so nothing dangles.

Symlinks

Symlinks stay symlinks. A link into the default profile is re-pointed into the copy. A relative link elsewhere (such as skills/x -> ../../.agents/skills/x) is resolved so it still works from the new location.

One-way sync, backups and pruning

sync only copies default → profile, because most tools assume the default config path. Before writing, it backs up the profile's settings.json, settings.local.json and .claude.json to <profile>/.mcc-backup/<timestamp>/. Files that exist only in the profile are kept unless you pass --prune, and pruning asks for confirmation (or needs --yes).

Configuration #

mcc keeps its environment and profile registry in ~/.mcc/config.toml. You can customize what sync and clone copy with a [sync] table:

[sync]
exclude = ["plugins"]          # built-in items to skip
extra = ["my-tool/config.yml"] # additional paths (relative to the config dir) to copy

A corrupt config.toml makes mcc exit with code 3 (invalid input) instead of guessing.

Usage limits #

mcc list shows 5-hour and weekly usage in its 5H and WEEK columns; mcc usage shows it in full.

$ mcc usage
◆ default ★  claude · me@example.com
    5-hour   ████████░░░░░░░░░░░░ 42% used · 58% left · resets in 2h 14m (Sat Oct 10 16:00)
    Weekly   ████░░░░░░░░░░░░░░░░ 18% used · 82% left · resets in 3d 4h (Wed Oct 14 00:00)

◆ lab  lab
    Usage    unavailable (not logged in)

◆ work  work · work@corp.com
    5-hour   █████████████████░░░ 85%! used · 15% left · resets in 35m (Sat Oct 10 14:21)
    Weekly   ███████████████████░ 96%!! used · 4% left · resets in 3d 4h (Wed Oct 14 00:00)

Reading the bars

Each bar is the share of the limit used. ! after the percent marks 80% or more and !! marks 95% or more. In a colour terminal the bar is also green, yellow (80%+) or red (95%+), but the markers carry the same meaning, so nothing depends on colour alone (--no-color, NO_COLOR or piped output).

Narrow terminals

When the output wouldn't fit the terminal, bars shrink. mcc usage first drops the absolute reset time and keeps the relative "resets in …", then shrinks its bar in the same 20 → 10 → 0 cell steps as mcc list --long. From 80 columns up a compact bar always stays; below 80 columns bars disappear (leaving 42% (2h)) when nothing fits. Set COLUMNS to override the detected width. Piped output gets full-size bars unless COLUMNS is set, and --json never has bars or colour.

Where the data comes from

mcc reads each profile's own Claude Code login (<config dir>/.credentials.json, or on macOS the login Keychain item Claude Code created for that config dir) and asks Anthropic's usage endpoint, https://api.anthropic.com/api/oauth/usage, the one behind Claude Code's /usage screen.

The endpoint is undocumented and may change. When it does, mcc shows "unavailable" rather than failing.

  • Never fatal. If usage can't be determined (logged out, expired login, offline, API error), the profile shows unavailable with the reason, the command still exits 0, and no warning is printed. Requests run in parallel with short timeouts: 2 s to connect, 4 s total.
  • Tokens stay private. A profile's access token is only sent to that endpoint, for its own profile. It is never printed, logged or written anywhere. mcc never refreshes tokens: if a login has expired, start the profile in Claude Code once (work, claude, …) and it refreshes itself.
  • Turn it off with mcc list --no-usage or MCC_NO_USAGE=1 (which also applies to mcc usage). Usage then shows — and nothing touches the network or the keychain.

JSON format

In mcc list --json every profile has a usage object. mcc usage --json prints one object per profile with name, command, is_default, account (or null) and the same usage object:

"usage": {
  "status": "ok",
  "reason": null,
  "five_hour": { "percent": 42.0, "resets_at": "2026-10-10T16:00:00Z" },
  "weekly":    { "percent": 18.0, "resets_at": "2026-10-14T00:00:00Z" }
}

status is ok or unavailable. five_hour and weekly are null when there is no data (resets_at can be null too). When status is unavailable, reason is one of:

reasonMeaning
not_logged_inNo Claude Code OAuth login found for the profile
token_expiredThe stored login has expired, or the API rejected it (HTTP 401); start the profile to refresh it
unauthorizedThe API refused the token (HTTP 403), for example a login without the profile scope
rate_limitedHTTP 429
networkOffline, timeout or connection failure
http_errorAny other HTTP status
parse_errorThe response wasn't the expected JSON
disabledNot fetched (--no-usage / MCC_NO_USAGE)

Alias rules #

An alias must be 1–32 characters: lowercase letters, digits, - or _, starting with a letter. It is rejected if any of these already uses the name:

  • mcc's reserved names: claude, mcc, default, help, all
  • shell keywords and builtins
  • existing mcc profiles
  • executables on $PATH
  • aliases and functions in your rc files (.zshrc, .bashrc, .bash_profile, .profile, fish config, …)
  • anything your interactive shell resolves with type <name>, which catches plugin-defined aliases

A rejected alias is a usage error (exit 2).

Troubleshooting #

The new command isn't found

The launcher lives in ~/.local/bin. If that directory isn't on your PATH, run mcc init --force; it checks and offers to add it. The shell alias only applies to terminals opened after mcc add.

Usage shows unavailable

Run mcc list --long or mcc usage to see the reason. For token_expired, start that profile in Claude Code once (for example work) so it refreshes its own login; mcc never refreshes tokens itself. For not_logged_in, run the profile's command and sign in.

claude isn't detected

Point mcc at the binary with MCC_CLAUDE_BIN=/path/to/claude, or put it on your PATH and run mcc init --force.

Something went wrong

Every run is logged to ~/.mcc/logs/mcc.log; add --verbose to see the same detail in the terminal. Your rc file backups are in ~/.mcc/backups/. If you think you've found a bug, open an issue. Report security problems privately as described in SECURITY.md.

Uninstall #

Delete every mcc profile (this logs each one out), remove the binary, then remove mcc's state. Your default ~/.claude profile is left alone.

$ for p in $(mcc list --json | jq -r '.[] | select(.is_default | not) | .name'); do mcc delete "$p" --yes; done
$ cargo uninstall mcc
$ rm -rf ~/.mcc
