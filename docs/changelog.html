What changed in mcc

Notable changes, newest first. The source of truth is CHANGELOG.md in the repository; the format follows Keep a Changelog and versions follow Semantic Versioning.

Unreleased

main

Added

  • mcc rename ALIAS NEW (alias mv): renames a profile and its command. It installs the new launcher and alias block, renames the registry entry, then removes the old launcher and alias. The new name is checked like an alias in mcc add, and a failure rolls the changes back. The profile directory, and so its login, is kept.
  • [usage] show_email in ~/.mcc/config.toml, plus --show-email / --hide-email on mcc usage, to choose whether account emails are shown.

Changed

  • mcc usage shows a compact table, one row per profile, instead of a block per profile: the bar and percent used, time until reset and reset time for the 5-hour and weekly windows. On narrow terminals the reset time goes first, then bars shrink 10 → 5 → 0.
  • mcc usage hides account emails by default, in the table and in --json (account is null).

Fixed

  • mcc delete <old name> refuses to delete a directory that a renamed profile still uses.

0.1.0

First version 2026-10-10

The first version of mcc. Release v0.1.0.

Added

  • Homebrew formula for macOS and Linux: brew install luongnv89/tap/mcc builds mcc from source and installs bash, zsh and fish completions. brew upgrade mcc and brew uninstall mcc work as usual. The formula lives in packaging/homebrew/mcc.rb. #14
  • mcc usage [PROFILE] [--json]: every profile's 5-hour and weekly usage in detail, with a bar, percent used and left, time until reset, and the reset time in local time. default or claude selects ~/.claude; an unknown name exits 2. #16, #20
  • Usage meters in mcc list: a coloured bar (green, yellow at 80%+, red at 95%+) and colour-independent ! / !! markers, sized to the terminal width. #17, #20
  • 5-hour and weekly usage in mcc list: new 5H and WEEK columns, lines in --long cards, and a usage object in --json, for every profile including the default. Each profile's own login is used; failures show unavailable with a reason and never change the exit status. #13, #15
  • --no-usage and MCC_NO_USAGE to skip the usage fetch, and the MCC_USAGE_URL / MCC_SECURITY_BIN test overrides. #15
  • mcc completions for bash, zsh, fish, elvish and PowerShell, plus install.sh. #12
  • mcc list (table, --long cards, --json), mcc sync (plan, backup, apply; --dry-run, --prune, --only, --all) and mcc delete (type-to-confirm or --yes, logout, removes only what mcc created). #12
  • mcc init (OS, terminal, shell, rc file and claude detection, run automatically on first use) and mcc add (alias validation, clone with path rewriting, launcher, managed rc block, login, rollback on failure). #12
  • Apache-2.0 license, contributing guide, code of conduct, security policy, and issue and pull request templates. #18, #19

Fixed

  • mcc usage keeps the full 20-cell bar at 80 columns: it drops the absolute reset time before shrinking the bar, and shrinks in the same 20/10/0 steps as mcc list --long. #21
  • Relative symlinks (such as skills/x -> ../../.agents/skills/x) are re-resolved from their source location, so cloned profiles don't get broken links. #12

Security

  • Access tokens are kept in memory only, sent only to the usage endpoint for their own profile, and never printed, logged or written to disk. Expired tokens are never sent. #15
  • GitHub private vulnerability reporting is enabled, and contact@luongnv.com is listed as the security contact. #21
