0.12.0

2026-11-24

mcc can now run a Claude Code profile on an Anthropic API key instead of a Claude login, and shows what it spent this month beside your other accounts. mcc usage can also show the accounts on your other computers, read over SSH. And a setting you change in any profile now reaches all your profiles when you sync, with a question first before a password or token is copied. Release v0.12.0.

Added

  • API-key profiles. mcc add api --api-key-prompt (or --api-key-stdin, to read the key from a pipe) adds a profile that uses an Anthropic API key instead of a Claude login, with no sign-in. mcc keeps the key in a file only you can read, under ~/.mcc/keys; with --api-key-helper CMD, your own command, such as a password manager's, supplies the key and mcc stores nothing. A key is never taken as a command-line argument. mcc list, mcc usage and mcc show these profiles in their own block, with an estimate of what each spent this month on this machine and, if you set one with --budget, how much of your monthly budget that is. mcc delete removes the key file mcc wrote. See mcc add.
  • The accounts on your other computers in mcc usage. List each machine once under [machines.NAME] with mcc config edit, and mcc usage reads it over SSH, with your own SSH keys, and prints one table per machine. An account you use on several machines shows its newest numbers everywhere, and no email or login leaves its machine. A machine that can't be reached never stops the command. Each machine needs this version of mcc or newer. See Other machines.
  • mcc warns you when ~/.mcc/config.toml contains a setting it doesn't recognize, such as a misspelling, and suggests the name you probably meant.

Changed

  • A Claude Code setting you change in any profile now reaches all your other profiles when you run mcc sync, instead of only settings changed in the default profile. The default's settings are backed up first.
  • Syncing asks before copying a password, token or other secret between profiles, never shows the secret itself, and never copies the settings that tie a profile to its own account, such as its API key or endpoint.
  • A profile with settings of its own, such as its own API endpoint, keeps them and still receives new shared settings.

Fixed

  • Hooks and status lines that call curl and then date -u are no longer mistaken for secrets when you sync.

0.11.0

2026-11-20

mcc now shows Devin beside your Claude Code accounts. mcc devin starts the Devin CLI with its own configuration and login, and once you are signed in to Devin, mcc list, mcc and mcc usage add a devin row with its daily and weekly quota and its overage balance. mcc never signs Devin in or writes its login, and asks Devin's API only with [usage] live = true (after a one-time note) or for mcc usage --all; otherwise it shows the last numbers it saw. mcc usage can now order its rows with --sort or the usage.sort setting, and by default lists accounts from least to most weekly usage, so the default profile's ★ row is no longer always first. The mcc list and mcc usage tables number their rows, and --json output gains a provider field. Release v0.11.0.

Added

  • Devin as a provider beside your Claude Code accounts. mcc devin [-- ARGS] starts the Devin CLI as it is (MCC_DEVIN_BIN, else PATH, else ~/.local/bin/devin): your arguments verbatim, no --config, no change to HOME, XDG_* or any other variable, so Devin uses its default configuration and its own login; --dry-run prints the command. mcc never signs Devin in and never writes its login ($XDG_DATA_HOME/devin/credentials.toml, else ~/.local/share/devin/credentials.toml) or ~/.local/bin/devin. When that login exists, mcc list, bare mcc and mcc usage add a devin row (mcc usage devin for Devin alone) with Devin's daily and weekly quota (never a 5-hour window) and its overage balance, read as custats-macos reads it: the session token goes to https://app.devin.ai/api (/organizations, then /<org>/billing/quota/usage). That lookup runs only with [usage] live = true, after a one-time note recorded as [usage] devin_disclosed_at, or for mcc usage --all, whose notice then names Devin's API; never with MCC_NO_USAGE, and never for bare mcc. Otherwise the last lookup's numbers are shown from ~/.mcc/providers/devin/quota.json, which keeps the organization but never the token. mcc doctor checks Devin when its CLI or login is there (warnings at most). devin is now a reserved profile name (an existing profile of that name keeps working). #124
  • mcc list --json and mcc usage --json (and --json-v2) objects end with a new provider field: "claude" for Claude Code profiles, "devin" for Devin's row, whose Claude Code counts are null and whose usage has daily and overage_usd. Schema 1 only gains fields; Claude Code profiles' usage objects are unchanged. #124
  • The mcc list / bare mcc table and the mcc usage table number their rows (#), so the last number is how many accounts you have; Devin's row in mcc usage carries on from the profiles' numbers. The number sits one space before the name, so the tables keep the widths they fit before (bars at 80 columns in mcc usage, every column at 120 in mcc list).
  • mcc usage orders its rows: --sort picks name (alphabetical), five-hour or weekly (percent used, least to most) or five-hour-reset / weekly-reset (soonest reset first) for one run, and [usage] sort = "…" (mcc config set usage.sort ORDER, "" for the default) changes the order it uses with no --sort, which is now weekly usage least to most — the default profile's ★ row is no longer pinned first. A profile missing the order's value sorts last, and Devin's row is appended after the table. mcc config get usage.sort prints the order in effect. --sort rejects an unknown value, naming the valid ones. #126

Fixed

  • The mcc-accounts eval grader evals/check_sandbox.py no longer adds its own claude call to the output it grades. With mcc 0.10.0, the bare mcc default it ran for global_default asks claude auth status, which the sandbox's fake claude logged, so claude_calls gained a call the agent never made (one more per run), and global_default was always default, so "default unchanged" checks could not fail. It now reads the logs before running any mcc command, runs only mcc project list, and replaces global_default with auth_changes (the claude auth login and auth logout calls through which mcc default switches an account from 0.10.0) and default_pointer (the default_profile an mcc 0.7.0–0.9.x mcc default PROFILE wrote to ~/.mcc/config.toml). evals.json grades "no account switched" from them. Eval tooling only: the shipped skill and mcc are unchanged. #122

0.10.0

2026-11-18

mcc default now changes the account of the default profile instead of pointing plain claude at another profile. ~/.claude is always the default profile. mcc default PROFILE trades accounts with PROFILE: after you confirm, ~/.claude signs out and in to PROFILE's account, and PROFILE signs out and in to the account ~/.claude had. mcc default --new signs ~/.claude in to another account and offers to keep the old one as a new profile. mcc only runs claude auth logout and claude auth login; it never reads, copies or moves a credential. The pointer an older mcc default PROFILE set up is removed on the next mcc command. Release v0.10.0.

Added

  • mcc here shows which profile, and so which account, mcc run starts in the current directory, and why: the default for DIR (set on this folder with mcc project set), inherited from parent folder DIR, or no project default here or in a parent folder (the default profile, ~/.claude). It prints the directory, the account (its organization; the email only with [privacy] show_email) and the profile's config directory, with a hint on how to change it. It resolves the profile through the same code as mcc run and the mcc status view, so they always agree. It is read-only, even before setup: no sign-in, no account switch, no lock, no first-run setup, no usage lookup, nothing written, not even a log line. Before mcc is set up it still answers (the default profile) and says mcc is not set up; a project default naming no profile is reported with a warning that mcc run stops there, and it still exits 0. #116

Changed

  • mcc default PROFILE trades accounts between ~/.claude and PROFILE. mcc shows both accounts and asks first (-y confirms; without a terminal and without -y it exits 2). ~/.claude signs out and in to PROFILE's account, then PROFILE signs out and in to the account ~/.claude had. Each sign-in page is pre-filled with the account it expects (--email; a Claude Code without that option gets a warning and blank pages), and mcc checks that the sign-in landed on that account, in the same organization, before the next step. mcc runs claude for these steps without the credential variables (ANTHROPIC_API_KEY…), so it sees each profile's stored login. In a terminal a mismatch offers another try; otherwise mcc stops, prints the state it left, and the command that recovers it (claude auth login --email ADDRESS for ~/.claude, mcc exec PROFILE -- claude auth login --email ADDRESS for the profile). A Ctrl+C during a sign-in stops the same way with exit 130. #115
  • As soon as ~/.claude is verified on PROFILE's account, mcc updates the registry, so a stop on PROFILE's side leaves it right: project defaults and allow lists that name default or PROFILE follow their account, so the two names trade places in them (asked before anything signs out; -y moves them, --keep-projects leaves them on their profile); PROFILE's recorded account, label and share_cross_org_allowed_at go, since they described the account it gave away; and both profiles' cached usage (usage.json) and failed-refresh mark (refresh-failed-at) in ~/.mcc/state/ are forgotten. Once PROFILE is verified, mcc records its new account under [profiles.PROFILE.account] and asks for a label (--label LABEL sets one, -y leaves none). Each profile keeps its history and sessions, so mcc warns before asking when the two accounts are not in the same organization: each can then resume what the other did there.
  • mcc default --new signs ~/.claude in to another account (--email ADDRESS pre-fills the sign-in page, --sso forces SSO). When no profile holds the account ~/.claude is leaving, mcc first offers to keep it as a new profile: mcc add ALIAS --clone, signed in to that account, before ~/.claude signs out. --keep-as ALIAS names it, and -y alone signs the account out of this machine. An --email that is a profile's account, or a sign-in that lands on one, is offered as a trade instead. Landing on the account ~/.claude already had stops. A profile counts as holding an account only while it is signed in to it. A Console sign-in on ~/.claude is signed out after a warning (no profile can keep it), and one Claude Code can't name is refused. --email needs a Claude Code whose claude auth login has it, and --email, --sso and --keep-as go with --new only (exit 2 otherwise).
  • Refused before anything signs out: a profile that is signed out, or signed in to the same account as ~/.claude; an Anthropic Console sign-in (API billing, which Claude Code keeps outside the profile's directory); a session-sharing profile that would share across organizations with the account it receives (stop sharing first with mcc share PROFILE --off); another mcc command refreshing either login. mcc default without arguments still prints default on stdout, and now says on stderr which account ~/.claude is signed in to (the email only with [privacy] show_email) and which profiles share it; it asks claude auth status to find out.
  • ~/.claude is always the default profile: outside projects, mcc run, mcc env and the mcc status view always use it. mcc list, mcc usage and mcc always mark it with ★, and is_global_default in --json and --json-v2 is true for default only. The hint mcc add prints when the default profile's account is already a profile's now names mcc default --new and mcc default PROFILE.
  • Workspace defaults: a folder's default profile (mcc project set, with --path for any folder such as a workspace that holds several repositories) applies in every folder below it that has none of its own, up to /; with none, ~/.claude. This was already how project defaults resolved; it is now documented, tested end to end, and visible: mcc run, mcc env and the mcc status view say inherited from parent folder ~/work when the default comes from a folder above the current one (the default for ~/work in that folder itself), and no project default here or in a parent folder instead of no project default here. #119

Removed

  • The pointer mcc default PROFILE kept from 0.7.0 to 0.9.x: default_profile in ~/.mcc/config.toml and the claude function in the rc file between # >>> mcc:default >>> and # <<< mcc:default <<<. The next mcc command removes both, together, and says so once; plain claude (in new shells) and mcc run then start ~/.claude again, and the profile still starts with its own command. mcc doctor reports a leftover pointer or rc block as a warning with mcc default as the fix. mcc rename and mcc delete no longer touch it, mcc config set default_profile explains that ~/.claude is always the default, and mcc default default (or claude) now exits 2. Upgrade note: if you used mcc default PROFILE so that plain claude started PROFILE, plain claude and mcc run start ~/.claude after the upgrade. To make PROFILE's account the default again, run mcc default PROFILE once: it now trades the accounts of ~/.claude and PROFILE, and asks first. Or start PROFILE with its own command or mcc run --profile PROFILE. Scripts that read is_global_default, run mcc default default or mcc config set default_profile, or match no project default here on stderr (now no project default here or in a parent folder) need updating. #115

Fixed

  • mcc add no longer asks you to sign in again when you are already signed in to Claude Code. When ~/.claude is missing, it used to create it and always run claude auth login, but on macOS the login lives in the Keychain and ~/.claude.json sits outside ~/.claude, so a missing ~/.claude doesn't mean signed out: the new sign-in replaced the login you had and the account in ~/.claude.json. mcc add now asks claude auth status first, without the credential variables (ANTHROPIC_API_KEY…) that would stand in for a stored login. Signed in: it keeps that login as the default profile's, skips the sign-in, and leaves ~/.claude.json as it is (it only adds hasCompletedOnboarding when that is missing); --email and --sso go unused, with a warning that names mcc default --new for switching to another account on purpose. Signed out: it signs in as before. When claude auth status gives no answer mcc can read, it creates ~/.claude without signing in, so it never replaces a login it can't see, and says to run claude or mcc login default. With ~/.claude present, as before, setting up mcc and mcc add ALIAS never sign the default profile out or in. #118

0.9.0

2026-11-08

This release makes no change to the mcc binary apart from its version number. It adds mcc-accounts, an agent skill that lets an AI agent use your profiles through mcc: tell which account a session or repository uses, report usage and login expiry, run a command or a headless claude -p task as a profile you name (mcc exec), and change mcc settings when you ask. It reads no tokens, hides emails, and never picks, ranks or runs an account because another one is at its limit. It works with mcc 0.7.0 and later. Release v0.9.0.

Added

  • mcc-accounts, an agent skill that lets an AI agent use the accounts mcc manages. It tells the profile a session runs as apart from the one mcc run would start in a directory, matching CLAUDE_CONFIG_DIR against each profile's folder, so a renamed profile whose folder keeps its old name still resolves. It reports each account's 5-hour and weekly usage and login expiry from mcc usage --json-v2, with the age of mcc's usage cache, and runs mcc usage --all only when asked for a live lookup. It runs a command, or a headless claude -p task, as a profile you name exactly with mcc exec, removing ANTHROPIC_API_KEY and the other credential variables mcc strips for its own claude runs for that one command and saying so. A headless task starts at once only when you gave its exact text and it needs no tool that writes; otherwise the skill shows the profile, prompt, directory and allowed tools and waits for a yes. It changes mcc state (project mappings, the default, sync, share) only on request, confirms destructive changes, checks each change with a read-only command, and hands interactive commands (mcc run, launchers, mcc login, mcc add) back to you. A description such as "my work account" picks nothing: the skill shows the profiles and asks. It reads no tokens, passes --hide-email unless asked for emails, and never picks, ranks or runs an account because another is at its limit, nor builds automatic switching: at a limit it reports when the limit resets and leaves the choice to mcc run, as mcc does. It needs mcc 0.7.0 or later, and Python 3 for its helper script (without Python, it follows manual steps). Install it from this repository with a skill manager, or from a clone copy skills/mcc-accounts/ into ~/.claude/skills/; see its installation and usage guide. #109

Fixed

  • The mcc-accounts skill now checks that mcc is set up the way mcc does: ~/.mcc/config.toml must load and hold a complete [env] table. Before, it only checked that the file existed, so a config.toml without [env] let it run mcc list, which started mcc's first-run setup. A missing, unreadable or incomplete file now stops it with "mcc is not set up yet" and changes nothing. #110
  • The mcc-accounts eval sandbox now works at a path that contains spaces: its fake claude writes its logs as tab-separated lines, so a space in the sandbox path no longer cuts it short. Eval tooling only: the shipped skill and mcc are unchanged. #111

0.8.0

2026-11-07

mcc usage --all now refreshes expired account tokens through Claude Code: when it finds an account's access token expired, it runs one tiny, one-turn Claude Code session as that profile, in a project mapped to it with mcc project set or, for a profile no project maps to, in a new empty folder, then looks the account up again and shows and caches the fresh usage. Each session is announced on stderr before it starts, naming the account and the folder, and uses a little of that account's quota; mcc never sends a refresh token itself. An account that can't be refreshed is named on stderr with mcc run --profile PROFILE to refresh it by hand, and the command still exits 0. Plain mcc usage, [usage] live = true and --json output are unchanged. Release v0.8.0.

Added

  • mcc usage --all refreshes expired account tokens through Claude Code: when its live lookup finds an account's access token expired, it runs one tiny, isolated one-turn claude -p session as that profile (the request mcc login --refresh-only makes) in the first existing project mapped to it with mcc project set (where mcc run starts it), or, for a profile no project maps to, in a new empty folder started as that profile (mcc run --profile), then looks that account up again and shows and caches the fresh usage. Each session is announced on stderr before it starts, naming the account and the folder (with -q too), and uses a little of that account's quota; mcc never sends a refresh token itself. No session starts for a logged-out account, a login past its deadline (mcc login PROFILE), a token the API rejected while still valid, a profile another mcc command is refreshing (~/.mcc/state/<profile>/refresh.lock, which mcc login --refresh-only now holds too), or one whose refresh failed in the last 30 minutes (refresh-failed-at); one run spends at most 3 minutes on refreshes. An account that can't be refreshed is named on stderr with mcc run --profile PROFILE to refresh it by hand, and the command still exits 0; Ctrl+C during a session stops the others, prints the table and exits 130. Plain mcc usage, [usage] live = true and --json output are unchanged. #106

Limits: ~/.claude stays the setup mcc sync and mcc add --clone copy from, and default/claude still name it in every command. command claude, IDEs and scripts still start ~/.claude. #104

0.6.0

2026-11-02

Profiles now catch up with the default profile as they start: auto sync, on by default, does the safe part of mcc sync when a profile starts from its launcher or with mcc run, copying only what the default added or updated, after a backup and keeping the profile's own edits (run mcc refresh-launchers once so existing launchers catch up). mcc usage now shows when each profile was last active and when its login ends, warning when one ends within 2 days by default, and the new mcc login PROFILE renews a login in place. Release v0.6.0.

Added

  • Auto sync: profiles catch up with the default profile as they start, so they no longer fall behind during a day of changes to the default. On by default ([sync] auto), starting a profile from its launcher or with mcc run first does the safe part of mcc sync for it, then for the other profiles the default changed for while a half-second budget lasts: only adds and updates, three-way against the profile's sync record, after a backup to <profile>/.mcc-backup/<timestamp>-auto/ (only the 10 latest auto sync backups are kept per profile; backups of mcc sync and mcc link are never removed). Local edits and conflicts are kept and still reported; it never prunes, never forces and leaves linked items alone, and nothing is written for a profile without a usable sync record, or when catching up would remove something or overwrite something its sync record doesn't cover yet (mcc list marks those (held); mcc sync ALIAS handles them). A launch stays fast: a fingerprint of what a catch-up depends on is kept per profile in ~/.mcc/state/<alias>/auto-sync.json, and nothing is compared while it is unchanged; mcc's lock is only tried, so a profile is skipped rather than waited for. Claude Code always starts, and nothing is written to its stdout; on a terminal one stderr line says what was copied. mcc list --long shows Auto sync, Last checked and Last auto sync, and --json adds auto_sync per profile. mcc config set sync.auto false turns it off for every profile and mcc config set profiles.ALIAS.auto_sync false for one; MCC_NO_AUTO_SYNC=1 turns it off for one run. Launchers call it only while auto sync is on for their profile: run mcc refresh-launchers once so existing launchers catch up (mcc list and mcc doctor report the ones that don't), and again after turning it off to take the call out. #99
  • Login expiry: mcc usage shows each profile's LAST ACTIVE (its newest prompt history or transcript; never .claude.json or the credentials, and for a session-sharing profile only its own history) and LOGIN ENDS (when its login needs a new sign-in, from Claude Code's refreshTokenExpiresAt), unknown when unknown, and warns on stderr for each profile whose login ends within [usage] login_warn_days (2 days by default, 1–14, mcc config set usage.login_warn_days), naming it and how to renew it. Plain mcc usage reads only the login deadline (refreshTokenExpiresAt) from .credentials.json, never a token nor the access token's expiresAt (mcc login --refresh-only additionally reads that), and nothing goes over the network; the macOS Keychain is read for them only with [usage] live = true or mcc usage --all, and MCC_NO_USAGE reads nothing. --json and --json-v2 add last_activity, login_expires_at, login_expires_source and login_warning. New mcc login PROFILE (alias mcc renew) signs the profile in again in place with claude auth login and succeeds only when the login deadline moved later and out of the warning window; signing in to another account or organization, or a session-sharing profile ending up across organizations, is reported as a failure. --refresh-only asks Claude Code to refresh the access token with one tiny isolated request instead (no browser), which usually leaves the deadline as it is and then says so. #100

0.5.0

2026-10-21

mcc usage --all looks up every account's usage live for one run, the default profile included, with no config change and a risk notice each time. What it finds is saved to the mcc statusline cache, so plain mcc usage, mcc list and mcc run show those numbers afterwards, with their age. Release v0.5.0.

Added

  • mcc usage --all looks every account's usage up live for one run, the default profile included, with each profile's own login instead of the mcc statusline cache, without turning on [usage] live = true. Because it sends each profile's OAuth access token to Anthropic's undocumented usage endpoint, it prints a risk notice on stderr every time it runs, also shown in mcc usage --help; use it only with accounts you own. What it finds is saved to the same cache mcc statusline writes, so a later mcc usage without --all, mcc list and mcc run show it with its age until a window resets or newer numbers are cached; an account it can't read keeps what was cached. Without --all, mcc usage behaves as before. #94

0.4.0

2026-10-21

Each project can now have its own profile, which mcc run starts, and usage now comes from what mcc statusline caches as you use Claude Code instead of from your logins. mcc sync keeps the changes you make inside a profile, profiles can share the default's plugins and link its skills, mcc doctor checks every profile's setup, and the install script downloads a prebuilt binary, so you no longer need Rust. Release v0.4.0.

Added

  • Per-project profiles. mcc project set PROFILE makes PROFILE the one mcc run starts in the current git repository (or directory). mcc never switches accounts on its own: when that profile is at its 5-hour or weekly limit, mcc run asks first, with waiting as the default, and offers other profiles only when the project allows them (--allow). mcc list shows each project's profile. #28, #31
  • mcc env [PROFILE] prints the shell line that points CLAUDE_CONFIG_DIR at the project's profile, so plain claude, IDE extensions and scripts use it too: eval "$(mcc env)", also in a direnv .envrc. mcc exec PROFILE -- CMD... runs any command as a profile, and mcc exec --all -- CMD... runs it once per profile. #42, #43
  • Opt-in mcc statusline install: Claude Code's status line saves each profile's 5-hour and weekly rate limits as you use it, so mcc can show usage without reading your logins. --prefix also puts the active profile's name in the status line, and mcc statusline uninstall puts the previous one back. #33
  • Shared plugins and link mode. mcc link ALIAS plugins makes a profile use the default profile's plugins instead of its own copy, and mcc link ALIAS skills,agents (also commands, output-styles and claude-md) links those items to the default's. Editing a linked item, or installing or removing a plugin in a sharing profile, changes it for the default too. --off gives the profile its own copy again. #46, #47
  • Per-profile settings overlays: [profiles.ALIAS.settings] in ~/.mcc/config.toml, or settings.mcc.json in the profile, keeps a profile's own model, permissions or other settings across syncs. #45
  • mcc doctor [PROFILE] checks every profile's setup and prints the fix for each problem; it only reads, and exits 1 when it finds one. mcc config get|set|edit|path changes mcc's settings instead of editing its file by hand, and refuses an invalid value. #44, #48
  • Labels and colors. mcc add asks for an optional label (--label), and --color gives the profile a color; both show in mcc list, mcc run and the status line, and mcc config set profiles.ALIAS.label or profiles.ALIAS.color changes them. mcc on its own prints a quick status of every profile, and an opt-in launch banner (mcc config set launch.banner true, then mcc refresh-launchers) shows the profile and its usage as it starts. #39, #54, #55, #59
  • Session-sharing groups. mcc share ALIAS --group NAME shares sessions only with the profiles of group NAME, and joining a group with a profile of another organization is refused unless you pass --allow-cross-org. mcc add records the account each profile signs in to and warns when another profile already uses it. Upgrade note: profiles that already share keep sharing as the default group, with nothing moved; if mcc warns that a group mixes organizations, move a profile to a group of its own with mcc share ALIAS --off, then mcc share ALIAS --group NAME. #39, #40
  • mcc add --email ADDRESS and --sso are passed to claude auth login, and mcc add warns when a profile signs in with an Anthropic Console account, which Claude Code doesn't keep separate per profile. #58
  • --json-v2 on mcc list, mcc usage and mcc project list prints versioned JSON, {"schema": 2, ...}, around the same objects; --json is unchanged. #49
  • Prebuilt binaries. Each release ships mcc for macOS and Linux on x86_64 and arm64, and the install script downloads the one for your platform, checks its SHA-256 checksum and installs it into ~/.local/bin, so you no longer need Rust. Upgrade note: earlier versions of the script installed into ~/.cargo/bin; if it warns that an old mcc there comes first on your PATH, remove it with cargo uninstall mcc. #53, #89

Changed

  • mcc sync is three-way: it keeps the changes you make inside a profile, reports a path changed on both sides as a conflict instead of overwriting it (--force overwrites it), and backs up everything it replaces. mcc diff ALIAS shows what differs, and mcc list has a SYNC column. Upgrade note: the first sync of a profile made before this release still replaces what differs from the default, after backing it up and listing each path; preview it with mcc sync ALIAS --dry-run. #41, #87
  • mcc list, mcc usage and mcc run read usage from the mcc statusline cache and no longer read any login by default. They show how old the numbers are, and — for a profile with nothing current cached. Upgrade note: run mcc statusline install so mcc can show each profile's usage (profiles pick it up on their next mcc sync); looking usage up with each profile's login is now opt-in, with mcc config set usage.live true. #34
  • mcc list hides account emails by default, like mcc usage, and account is null in --json. Upgrade note: pass --show-email, or run mcc config set privacy.show_email true, to see them. #57
  • The mcc list table fits 120 columns: NAME, ACCOUNT, 5H, WEEK, LAST USED and SYNC. Counts, sizes and other details moved to mcc list --long; JSON is unchanged. #56
  • mcc add --clone shares the default profile's plugins instead of copying them; --copy-plugins gives the profile its own copy, as before. Upgrade note: start such a profile with its own command, mcc run, mcc exec or mcc env: plain CLAUDE_CONFIG_DIR=… claude sees no plugins. Existing profiles keep their copy until mcc link ALIAS plugins, which moves it to the profile's .mcc-backup/ folder; delete that backup to free the space. #47
  • The session-sharing note is printed in full only the first time sharing is turned on for a profile, and mcc's terms-of-service notes mention Anthropic's updated Usage Policy that takes effect November 12, 2026. #36, #38
  • link, project, run, env, exec, statusline and doctor are reserved and can't be used as aliases. #28, #33, #42, #43, #44, #46

Fixed

  • Comments you write in ~/.mcc/config.toml are kept when mcc saves it, and two mcc commands running at once no longer lose each other's changes. #35
  • ~/.mcc/logs/mcc.log no longer grows without limit: at about 1 MB it is moved to mcc.log.1, so at most about 2 MB of log is kept. #51
  • mcc sync backs up every file or folder it overwrites or removes, such as CLAUDE.md, skills and agents, not only the settings files. #30
  • mcc add no longer warns about a duplicate account when the same login is used in another organization, such as a personal plan and a work seat, since those have usage limits of their own. #40
  • The live usage lookup finds a profile's macOS Keychain login when USER is unset, as under launchd, cron or some IDE tasks. #37
  • A link entry in ~/.mcc/config.toml that can't be linked, such as a hand-written link = ["settings"], no longer makes mcc sync, mcc diff and mcc list skip that item; it is ignored with a warning. #86
  • The address given to mcc add --email no longer appears in mcc.log. #88

Security

  • The install script downloads release files over HTTPS only, redirects included, and builds from a local clone only when it runs as that clone's install.sh. Piped to sh, earlier versions took the current directory for a clone and built and installed it whenever its Cargo.toml had name = "mcc". #53

0.3.0

2026-10-13

Profiles can now opt in to session sharing with mcc share ALIAS or ALIAS --mcc-share, so --resume lists the sessions of every sharing profile, and mcc refresh-launchers updates launchers and shell aliases made by an older mcc. Release v0.3.0.

Added

  • Opt-in session sharing between profiles, off by default. mcc share ALIAS (or starting a profile with ALIAS --mcc-share) links the profile's projects/ to ~/.mcc/shared/projects, so --resume lists the sessions of every sharing profile. mcc share ALIAS --off gives the profile its own copy again. The setting is share_sessions under [profiles.ALIAS] in ~/.mcc/config.toml. Only sessions are shared: never credentials, the account, history or live session state. Every time sharing is turned on, mcc prints a note about Anthropic's Consumer Terms and Usage Policy. mcc list marks sharing profiles, and --json has share_sessions and launcher_current. #25, #26
  • mcc refresh-launchers [ALIAS...] rewrites launchers and shell aliases from the current templates. #25, #26

Changed

  • New launchers handle --mcc-share, and new shell aliases run the launcher instead of calling claude directly. CLAUDE_CONFIG_DIR is unchanged, so logins are kept. Upgrade note: existing launchers and aliases are not modified; run mcc refresh-launchers once to use ALIAS --mcc-share with profiles created before this release. #25, #26
  • mcc list prints a hint to run mcc refresh-launchers while a launcher predates session sharing. #25, #26
  • share and refresh-launchers are reserved and can't be used as aliases. #25, #26

0.2.0

2026-10-13

mcc usage is now a compact table that hides account emails by default, and mcc rename renames a profile and its command while keeping its login. Release v0.2.0.

Added

  • mcc rename ALIAS NEW (alias mv): renames a profile and its command. It installs the new launcher and alias block, renames the registry entry, then removes the old launcher and alias. The new name is checked like an alias in mcc add, and a failure rolls the changes back. The profile directory, and so its login, is kept. #24, #23
  • [usage] show_email in ~/.mcc/config.toml, plus --show-email / --hide-email on mcc usage, to choose whether account emails are shown. #24, #23

Changed

  • mcc usage shows a compact table, one row per profile, instead of a block per profile: PROFILE, then the bar and percent used, time until reset and reset time for the 5-hour and weekly windows. On narrow terminals the reset time goes first, then bars shrink 10 → 5 → 0. #24, #23
  • mcc usage hides account emails by default, in the table and in --json (account is null). Use --show-email or [usage] show_email = true to show them. #24, #23
  • mcc add <old name> names the renamed profile that still uses that name's directory, instead of only saying that the directory exists. #24, #23

Fixed

  • mcc delete <old name> refuses to delete a directory that a renamed profile still uses. #24, #23

0.1.0

First version 2026-10-10

The first version of mcc. Release v0.1.0.

Added

  • Homebrew formula for macOS and Linux: brew install luongnv89/tap/mcc builds mcc from source and installs bash, zsh and fish completions. brew upgrade mcc and brew uninstall mcc work as usual. The formula lives in packaging/homebrew/mcc.rb. #14
  • mcc usage [PROFILE] [--json]: every profile's 5-hour and weekly usage in detail, with a bar, percent used and left, time until reset, and the reset time in local time. default or claude selects ~/.claude; an unknown name exits 2. #16, #20
  • Usage meters in mcc list: a coloured bar (green, yellow at 80%+, red at 95%+) and colour-independent ! / !! markers, sized to the terminal width. #17, #20
  • 5-hour and weekly usage in mcc list: new 5H and WEEK columns, lines in --long cards, and a usage object in --json, for every profile including the default. Each profile's own login is used; failures show unavailable with a reason and never change the exit status. #13, #15
  • --no-usage and MCC_NO_USAGE to skip the usage fetch, and the MCC_USAGE_URL / MCC_SECURITY_BIN test overrides. #15
  • mcc completions for bash, zsh, fish, elvish and PowerShell, plus install.sh. #12
  • mcc list (table, --long cards, --json), mcc sync (plan, backup, apply; --dry-run, --prune, --only, --all) and mcc delete (type-to-confirm or --yes, logout, removes only what mcc created). #12
  • mcc init (OS, terminal, shell, rc file and claude detection, run automatically on first use) and mcc add (alias validation, clone with path rewriting, launcher, managed rc block, login, rollback on failure). #12
  • Apache-2.0 license, contributing guide, code of conduct, security policy, and issue and pull request templates. #18, #19

Fixed

  • mcc usage keeps the full 20-cell bar at 80 columns: it drops the absolute reset time before shrinking the bar, and shrinks in the same 20/10/0 steps as mcc list --long. #21
  • Relative symlinks (such as skills/x -> ../../.agents/skills/x) are re-resolved from their source location, so cloned profiles don't get broken links. #12

Security

  • Access tokens are kept in memory only, sent only to the usage endpoint for their own profile, and never printed, logged or written to disk. Expired tokens are never sent. #15
  • GitHub private vulnerability reporting is enabled, and contact@luongnv.com is listed as the security contact. #21
