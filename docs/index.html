Run every Claude Code account side by side.

mcc gives each account its own login, its own command, and a copy of your main setup. Type work for one account and claude for the other. No logging out in between.

The problem

Claude Code has one config directory. You have more than one account.

Your login, settings, skills, agents and MCP servers all live in ~/.claude. That holds up until a second account shows up.

Scenario 01

A personal plan and a company plan

You use your own subscription for side projects and your employer's for work, and the two should never share a session.

Scenario 02

A limit hit in the middle of a task

Your 5-hour window runs out halfway through a refactor. The account that still has room is one logout and one login away.

Scenario 03

Client work on the client's seat

A client pays for the account, so the sessions, history and billing for their project belong on their login, not yours.

The workarounds

Each workaround costs you something.

  • Logging out and back inEvery switch breaks your flow, and every new session runs on whichever account you touched last.
  • Setting CLAUDE_CONFIG_DIR by handYou get a bare profile. None of your skills, agents, hooks, plugins or MCP servers come with it.
  • Copying ~/.claude yourselfThe copy drags credentials along, keeps paths that point back at the original directory, and falls out of date the day you add a skill to your main setup.
  • Guessing which account has roomNothing shows the 5-hour and weekly limits of all your accounts in one place, so you find out when a session stops.
What mcc does

One command per account. One setup across all of them.

A command for each account

mcc add work creates ~/.mcc/profiles/work, a work launcher and a shell alias, then opens the login. claude stays exactly as it was.

Your setup, without your login

Cloning copies settings, CLAUDE.md, skills, agents, commands, hooks, plugins and MCP servers. Credentials, history and sessions stay behind, and paths to copied items are rewritten to the new profile.

Sync when your main setup changes

mcc sync work pulls new skills, plugins and settings from your default profile. Preview it with --dry-run; the profile's settings are backed up before anything is written.

Every limit on one screen

mcc usage shows each account's 5-hour and weekly usage and when it resets. Anything at 80% gets a !, at 95% a !!, so it reads the same without colour.

Every change can be undone

A failed add rolls itself back. Your rc file is backed up before each edit. mcc delete logs the profile out and removes only what mcc created.

Why not just a shell alias?

An alias sets one variable. mcc also checks the name against every command your shell knows, copies and rewrites your setup, runs and verifies the login, and keeps the profile in sync later.

mcc usage

See which account has room before you start.

Each profile is checked with its own login, in parallel, with short timeouts.

  • Percent used and left, time until reset, and the reset time in your time zone
  • Bars shrink to fit narrow terminals; --json for scripts
  • A logged-out or offline profile shows unavailable and the reason. The command still exits 0
  • Turn it off with --no-usage or MCC_NO_USAGE=1, and nothing touches the network
How it works

Three commands to a second account.

Install

Install mcc with Homebrew on macOS or Linux. It needs Claude Code.

$ brew install luongnv89/tap/mcc
Add a profile

Clone your default setup into a new profile, then finish the sign-in in your browser.

$ mcc add work --clone
Run it

Start Claude Code on that account by typing its name. Your default claude keeps working.

$ work

Built on the variable Claude Code already reads

Claude Code takes its config from CLAUDE_CONFIG_DIR, which defaults to ~/.claude. An mcc profile is a directory plus a launcher that sets that variable. Nothing is patched or wrapped.

FAQ

Questions before you install

Does mcc copy or share my login between profiles?

No. Each profile signs in separately through claude auth login. Clone and sync never copy credentials or account identity (oauthAccount, userID), and never copy history, sessions or projects.

Will it change my existing claude setup?

No. Your default profile stays in ~/.claude and keeps the claude command. Sync is one-way: it copies from the default into a profile, never back.

What does mcc send over the network?

Only mcc list and mcc usage make requests, to Anthropic's usage endpoint, each profile with its own token. The token is never printed, logged or written to disk. mcc has no telemetry or analytics. Details are on the privacy page.

Is the usage data official?

It comes from the same endpoint as Claude Code's /usage screen. That endpoint is undocumented and may change. If it does, mcc shows unavailable instead of failing.

Which platforms and shells are supported?

macOS and Linux, with zsh, bash or fish. mcc detects your shell and rc file on first run. Windows is not supported.

Do I need Rust?

Not with Homebrew: brew install luongnv89/tap/mcc builds mcc with Homebrew's own Rust. The install script and cargo install build from source with your cargo (Rust 1.88 or newer). Get Rust from rustup.rs.

How do I remove a profile, or mcc itself?

mcc delete work logs the profile out, clears its keychain entry, and removes its directory, launcher, shell alias and registry entry. To remove mcc entirely, see Uninstall.

Install

Give your next account its own command.

Free and open source under Apache-2.0. You need Claude Code. Building from source also needs Rust (cargo).

Start the quick start View the source

Homebrew (macOS and Linux)

$ brew install luongnv89/tap/mcc

One-liner

$ curl -fsSL https://raw.githubusercontent.com/luongnv89/mcc/main/install.sh | sh

With Cargo

$ cargo install --git https://github.com/luongnv89/mcc --locked

From a clone

$ git clone https://github.com/luongnv89/mcc && cd mcc && ./install.sh

Then run mcc add work --clone. First run detects your OS, shell and rc file automatically.
