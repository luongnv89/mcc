Run every Claude Code account side by side.

Claude Code keeps one login in ~/.claude. mcc gives each account its own command and a copy of your setup: work for one, claude for the other.

The problem

Claude Code has one config directory. You have more than one account.

  • A personal plan and a company plan
  • A limit hit in the middle of a task
  • Client work on the client's seat

What mcc does

One command per account. One setup across all of them.

A command for each account

mcc add work builds the profile, its launcher and a shell alias, then opens the sign-in. claude stays exactly as it was.

  • A failed add rolls itself back
  • mcc add

Profiles that run on an API key

Paying with an Anthropic API key instead of a subscription? The key goes in by pipe or hidden prompt, never as an argument, and the profile needs no sign-in.

  • Key kept in a 0600 file
  • Spend against a budget you set
  • API-key profiles

Every limit on one screen

mcc usage shows each account's 5-hour and weekly usage and when it resets. Anything at 80% gets a !, at 95% a !!, so it reads the same without colour.

  • Reads no token, touches no network
  • Emails hidden by default
  • mcc usage

Devin beside your accounts

Signed in to the Devin CLI? mcc devin starts it with its own settings and login, and its daily and weekly quota shows up beside your accounts.

  • mcc only reads Devin's login
  • mcc devin

Your other machines, over SSH

List a machine once in ~/.mcc/config.toml. mcc usage then reads its accounts over SSH with your own keys, one table per machine. The same machine can take tasks: mcc remote work lab "list failed systemd units" has work run commands there over SSH, with no Claude Code or mcc on it.

[machines.lab]
host = "me@lab-box"
  • No login or token leaves any machine
  • Multiple machines
  • mcc remote

Each project on its own account

mcc project set work makes work the profile mcc run starts in this repository. At its limit, mcc run asks first, with waiting as the default.

  • mcc never switches accounts for you
  • Per-project profiles

Sync when your main setup changes

mcc sync work pulls new skills, settings and MCP servers from your default profile and keeps the changes you made in the profile.

  • Every overwritten file is backed up first
  • Auto sync is on by default

Also included

The parts you need less often.

Rollback and backups

A failed add rolls itself back. Your rc file is backed up before each edit.

mcc doctor

Checks every profile and prints a fix for each problem.

Login expiry warnings

A warning two days before a login ends, by default. mcc login work renews it in place.

Opt-in session sharing

mcc share work lets --resume list sessions across your own profiles. Only sessions are shared, never logins.

Ask your agent about your accounts

The mcc-accounts agent skill lets an AI agent answer from mcc. It reads no tokens.

Shared plugins

A clone shares your default's plugins instead of copying them.

Why not just a shell alias?

An alias sets one variable. mcc also checks the name against every command your shell knows, copies and rewrites your setup, runs and verifies the login, and keeps the profile in sync later.

FAQ

Questions before you install

Does mcc copy or share my login between profiles?

No. Each profile signs in separately through claude auth login, or uses its own API key. Clone and sync never copy credentials, account identity, history, sessions or projects. A password or token in your shared settings is copied to another profile only after you agree, and is never shown.

Does mcc switch to another account when one hits its limit?

No. mcc run asks you to wait (the default), start it anyway, or pick a profile the project allows. Anthropic's seat rules and terms rule out automatic switching; see Per-project profiles.

Will it change my existing claude setup?

Your default profile stays in ~/.claude and keeps the claude command, and you don't sign in again. Five things do reach it: a settings.json key you change in a profile (through mcc sync, after a backup), plugins a cloned profile shares with it, items you link with mcc link, the opt-in mcc statusline install, and mcc default, which asks first. The docs cover each one.

What does mcc send over the network?

By default, nothing: mcc list, mcc usage and mcc run read the usage mcc statusline cached on your machine. The live lookup is opt-in (mcc usage --all, with a risk notice each time), and machines you list are read over SSH with your own keys. mcc remote runs the commands Claude writes on a machine you name, over SSH, and sends no login or token to it. A login token is never printed, logged or written to disk. Details are on the privacy page.

Is the usage data official?

By default it is what Claude Code itself passes to its status line, which mcc statusline caches. The opt-in live lookup uses the same endpoint as Claude Code's /usage screen. That endpoint is undocumented and may change. If it does, mcc shows unavailable instead of failing.

Which platforms are supported, and do I need Rust?

macOS and Linux, with zsh, bash or fish. Windows is not supported. You don't need Rust with Homebrew, or with the install script when the release has a prebuilt, checksum-verified binary for your platform. Building from source needs cargo (Rust 1.88 or newer).

How do I remove a profile, or mcc itself?

mcc delete work logs the profile out, clears its keychain entry, and removes its directory, launcher, shell alias and registry entry. To remove mcc entirely, see Uninstall.
